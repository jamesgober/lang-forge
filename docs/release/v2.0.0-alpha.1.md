# lang-forge v2.0.0-alpha.1 — LSF2, the Format-2 Sketch

**The first pre-release of lang-forge 2.0.** A sketch that says
`[sketch] format = 2` now gets LexerSketch's full syntax: token classes of its
own, lexer modes with a mode stack, string classes with interpolation,
heredocs and raw delimiters, contextual and case-insensitive keywords,
indentation layout, labelled fields on the tree's edges, predicates and text
back-references, injections, and `[ast]` supertypes — enough to forge Mox,
LexerSketch's PHP-heritage flagship, from its sketch and parse its templates
and scripts without a diagnostic. Forged languages save to deterministic
images that load without forging; sketches can span several files; and every
diagnostic carries a stable code.

A format-1 schematic — no `[sketch]` table, or `format = 1` — forges and
parses exactly as in 1.x. The breaking changes are small (rendered
diagnostics show their code; `Kind` is four bytes) and come with a migration
guide.

## What is lang-forge?

LexerSketch: describe a language in a short `.lsf` sketch — its tokens, its
grammar, its operators and their precedence, the capabilities it includes —
and `Language::from_lsf` forges a working front end for it. The forged
language lexes and parses source text into the family's lossless
`syntax-lang` tree, reports every problem as a `diag-lang` diagnostic, never
fails and never panics, and wires the sketch's capabilities into a
`pass-lang` pipeline.

## What's new

### Format 2 (LSF2)

```rust
use lang_forge::Language;

let lang = Language::from_lsf(r##"
[sketch]
format = 2

[language]
name = "page"
version = "1.0.0"

[lexer]
initial_mode = "html"

[lexer.keywords]
contextual = ["await"]

[lexer.tokens]
OPEN  = { literal = "<?", modes = ["html"], action = "switch main" }
CLOSE = { literal = "?>", action = "switch html" }
VAR   = { regex = '\$[a-z_]+' }

[lexer.modes.html]
tokens = ["OPEN"]
text   = "HTML"

[lexer.strings.DQ]
open        = '"'
interpolate = [{ open = "{", when_next = '\$', close = "}", rule = "expr" }]

[rules]
page = "(HTML | OPEN stmts:stmt* CLOSE)*"
stmt = "'echo' value:expr ';'"

[rules.expr]
operand = "VAR | DQ | IDENT"
levels  = [{ left = ["."] }, { prefix = ["await"] }]
"##)?;

let parse = lang.parse("<p><? echo \"Hi {$name}\" . await $rest; ?></p>");
assert!(!parse.has_errors(), "{:?}", parse.diagnostics());
assert!(parse.dump().contains("op:await"));
# Ok::<(), lang_forge::Error>(())
```

- **Token classes** (`[lexer.tokens]`): regexes and fixed texts with
  conditions (`followed_by`, `when_prev`, `line_start`, `column`),
  priorities, trivia classes, and mode actions. The regex dialect compiles
  to one DFA per class when the sketch is forged, under an automaton budget.
- **Modes** with a mode stack, `text` fallback classes for template text,
  `inherit`, `eof` policies, and a run-time depth budget.
- **String classes**: delimiter parts (`capture`/`backref` for `r#"…"#` and
  heredocs, `regex`, `newline`), interpolation holes parsed by a rule,
  embedded tokens parsed as self-injections, escape tokens, `close_at` line
  starts. Strings with structure build nodes of generated, labelled kinds.
- **Keywords**: contextual (`async`, `await` are names everywhere the grammar
  does not ask for the keyword), reserved, contextual-by-default (SQL), and
  case-insensitive.
- **Layout**: the offside rule with `INDENT`/`DEDENT`, joins, tabs, and
  newline modes.
- **Rule language v2**: field labels `cond:expr`, predicates `&e` and `!e`,
  text back-references `IDENT=name`, `WORD`, `EOF`, `LINE_START`,
  `NL_BEFORE`; table rules with `sync`, `allow`, `doc`; `prec`.
- **The overlap check** (`LSF4301`): a greedy `*`, `+`, or `?` that would
  silently reject valid input is refused with a witness input, unless the
  rule says `allow = ["overlap"]`.
- **Injections**, validated **hooks**, and **`[ast]`** supertypes.

Every key of LSF2's syntax sections, with its status, is in the
[coverage table](../API.md#lsf2-coverage). The keys this alpha does not do
are refused with `LSF1007` — never silently ignored — and scheduled for
alpha.2 in the ROADMAP.

### Fields on the tree's edges

Labels are stored in each child's `Kind`, so every format-2 tree carries its
fields. `Language::field_label(parent, index)` has the shape of lower-lang's
`Labeler::label`, so the adapter is one line; `Language::fields(kind)`
derives each node kind's fields with their kinds and `Cardinality`.

### Images, multi-file sketches, codes, kinds

- `Language::to_image` / `Language::from_image`: a forged language as
  deterministic bytes, versioned by `IMAGE_FORMAT`, fully validated on load
  (property tests load mutated images and parse with whatever loads).
- `Sketch` and `Language::from_sketch`: an entry and its parts, merged as one
  document, with diagnostics located through a `SourceMap`; portable,
  normalized paths.
- Diagnostic codes on every diagnostic, in both formats: `LSF` for sketches,
  `LF0xxx` lexical and `LF1xxx` parse errors in source.
- A public, dense kind index: `Kind::index`, `Language::kind_count`,
  `kind_at`, `root_kind`.

### Fixed

- **P09:** memoized parsing could disagree with unmemoized parsing near the
  depth limit; memo entries now record how deep they went.
- **P10:** the left-recursion check is one strongly-connected-components
  pass, and suggestions run a banded edit distance under one shared budget.

## Breaking changes

- Rendered diagnostics show their code: `error[LF1000]: expected …` where
  1.x rendered `error: expected …`. Messages and `Error`'s `Display` are
  unchanged.
- `Kind` is four bytes (it carries a field label in format-2 trees); its
  comparisons ignore the label.
- `diag-lang` 1.1 is required.

See the [migration guide](../../CHANGELOG.md#200-alpha1---2026-10-09).

## Mox

The flagship sketch forges (`tests/sketches/mox.lsf`, about 1,000 lines) and
its representative script and template parse with no diagnostic: `<?mox …
?>` and `<?= … ?>` islands over HTML, `$variables`, `"…{$x}…"` and `"$row[key]"`
interpolation (the simple forms parsed as self-injections), heredoc and
nowdoc, classes, traits with `insteadof`/`as`, enums, closures, `match`,
generators, casts, and `async`/`await`/`spawn` as contextual keywords.

The overlap check found one divergence the flagship does not acknowledge:
`elseif_clause`'s optional `else:` (the same case as `if_stmt`, which says
`allow = ["overlap"]`). The test copy adds the same allowance; the flagship
sketch needs it too.

## Measurements

Criterion, Windows x86_64, release profile, on a shared machine. 1.0.1 and
2.0.0-alpha.1 were built from their sources and run alternately, twice, so
both see the same load; the ranges are the two runs (±5 % is noise here).

| Benchmark (format 1) | 1.0.1 | 2.0.0-alpha.1 |
|---|---:|---:|
| `forge/mini` | 27.3–28.4 µs | 28.4 µs |
| `forge/json` | 10.4–10.7 µs | 11.6–11.7 µs |
| `forge/calc` | 10.7–11.0 µs | 11.0–11.6 µs |
| `lex/mini/1MB` | 2.60–2.63 ms | 2.59–2.67 ms |
| `lex/json/1MB` | 2.68–2.71 ms | 2.70–2.85 ms |
| `parse/speculative/256KB` | 23.0–25.1 ms | 23.1–24.5 ms |
| `parse/speculative/nested_60` | 22.5–23.9 ms | 23.3–24.9 ms |
| `parse/mini/4KB` | 70–79 µs | 73–80 µs |
| `parse/mini/1MB` | 34.5–43.2 ms | 34.8–34.9 ms |
| `parse/json/1MB` | 36.4–36.5 ms | 37.1–38.0 ms |
| `parse/calc/chain_100k` | 25.0–25.2 ms | 26.8–28.0 ms |
| `parse/mini/errors` | 14.6 ms | 16.1–17.3 ms |

Lexing and parsing valid format-1 input are within noise of 1.0.1. Three
paths are measurably slower: forging (up to about 1 µs, 0–10 %), the
100,000-operand operator chain (6–12 %), and the error-heavy input (10–19 %,
where every diagnostic now carries a code and diag-lang 1.1's diagnostics are
larger). An early build of this release was 20–34 % slower on speculation,
because a four-byte `Kind` made each parser event 12 bytes; events are now
packed into 8 bytes, as in 1.x.

Format 2, the Mox sketch and sources (Windows, same machine):

| Benchmark | Time |
|---|---:|
| `v2/forge/mox` — forge the ~1,000-line Mox sketch | ~23 ms |
| `v2/image/mox/to` — write its image (209 KB) | ~0.19 ms |
| `v2/image/mox/from` — load and validate the image | ~0.25 ms |
| `v2/lex/mox_script/1MB` | ~12.7 ms (79 MiB/s) |
| `v2/parse/mox_script/1MB` | ~67–73 ms (14 MiB/s) |
| `v2/lex/mox_template/256KB` | ~2.2 ms (112 MiB/s) |
| `v2/parse/mox_template/256KB` | ~7.4–7.7 ms (33 MiB/s) |

Most of forging Mox is the overlap check (about 20 ms); loading the image
instead skips all of it. The mode-stack scanner is about five times slower
per byte than format 1's derived lexer on code: it consults a DFA per
active token class and the mode stack at every token, where format 1
dispatches on one byte table.

## Verification

Run on Windows x86_64 with stable (1.95), 1.99, and the 1.85 MSRV:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings              # also +1.85, +1.99
cargo clippy --all-targets --no-default-features -- -D warnings       # also +1.85, +1.99
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo test --all-features
cargo test --no-default-features
cargo +1.85 test --all-features
cargo bench --no-run
```

All green. Counts (identical for every feature combination): 114 unit
(including 6 parser properties) + 42 forging (1.x, kept) + 20 parsing (1.x,
kept) + 7 properties (1.x, kept) + 21 regressions (1.x, kept) + 3 memory +
28 format-2 lexer + 23 format-2 grammar + 9 Mox + 7 multi-file sketch + 5
image (3 properties) + 7 format-2 regressions + 121 doctests. The property
tests were also soaked at 20,000 cases each. About 27–31 % of single-byte
mutations of a sealed image still load (the rest are refused), and every one
that loads parses without panicking.

## What's next

alpha.2: sketch composition (`extends`, `[compose]`, mixins), token
splitting, column trivia, hooks that run (scanner, reclassify, predicate,
layout), `%mode(...)`, rule-scoped newlines, soft terminators, dynamic
operators, `rest_of_line = "code"`, injection `when`, combined
self-injections, and the remaining checks — each listed with its reason in
[`dev/ROADMAP.md`](../../dev/ROADMAP.md).
