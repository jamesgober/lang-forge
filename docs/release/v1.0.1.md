# lang-forge v1.0.1 — Hardening

**A patch from the LexerSketch audit.** v1.0.1 fixes a parser flag that let
one deeply nested construct degrade parsing for the rest of the file, makes
the speculation memo's memory independent of nesting depth, puts budgets on
what a hostile schematic can make forging allocate, reads schematics as
strictly as NOML and TOML require, treats a leading byte-order mark as
trivia, and corrects documentation that claimed more than the crate does.
The public API and the `.lsf` format are unchanged.

## What is lang-forge?

LexerSketch: describe a language in a short `.lsf` schematic — its tokens, its
grammar, its operators and their precedence, the capabilities it includes —
and `Language::from_lsf` forges a working front end for it. The forged language
lexes and parses source text into the family's lossless `syntax-lang` tree,
reports every problem as a `diag-lang` diagnostic, never fails and never
panics, and wires the schematic's capabilities into a `pass-lang` pipeline.

## Breaking changes

**None to the API.** Some schematics 1.0.0 forged are now refused. Each is
invalid NOML or hostile:

- a `[header]` that defines a table already defined by dotted keys
  (`expr.operand = "..."` and then `[rules.expr]`) — write one form or the
  other;
- a multi-line string (`"""..."""`, `'''...'''`) used as a key;
- a block-comment pair with anything but two strings (`["/*", 1, "*/"]`);
- a schematic over 8 MiB, one nesting more than 64 levels deep in total, or
  one whose parser tables would exceed 256 MiB.

## Fixed

- **Speculation after a too-deep construct.** Once any construct hit the
  768-level depth limit, every later speculative choice in the file tried only
  its first alternative, so valid code after it — `x;` where the grammar tries
  an assignment first — was reported as an error. The flag is now cleared
  when an outermost speculation begins and ends. Inside a speculation it still
  limits each decision to one attempt, which is what keeps speculation over
  too-deep input linear.
- **Memo memory grew with nesting depth.** The memo copied the events of
  every successful strict attempt, at every level. It now leaves them where
  the parser produced them and moves them only when a rewind would discard
  them, once, keeping nested replays as references.
- **Byte-order marks.** A leading UTF-8 BOM in source text was an `UNKNOWN`
  character with an error; it now begins the first `WHITESPACE` token
  (lossless, and never reported). In a schematic it is skipped. Spans still
  count it.
- **Strict NOML.** Malformed numbers, dates, and times (`1abc`, a lone `-`,
  `0123`, `1979-13-01`) are errors instead of being read as some number;
  well-formed ones — TOML integers, floats, `inf`, `nan`, RFC 3339 dates and
  times — are read and reported as the wrong type, since no setting takes one.
  Dotted-key tables cannot be redefined by headers, and keys cannot be
  multi-line strings.
- **Block comments.** A non-string item in a block-comment pair is an error,
  not silently dropped.
- **Documentation.** The crate docs, README, API reference, and manifest no
  longer say forged trees "plug straight into" the formatter, incremental
  reparser, language server, and tree-sitter crates: they are the trees those
  crates are designed to consume, and the adapters arrive with LexerSketch.
  `Language::kind_name` documents (and doctests) that another language's kind
  gets a wrong name or `"<unknown>"`. The schematic layout example in the
  source is now a forgeable schematic, checked by a test. The roadmap's
  `grammar-lang` note is current.

## Security

- **Table budget.** FIRST, FOLLOW, and recovery sets are bitsets over every
  token kind, and there were several per grammar expression, so a few
  megabytes of schematic could demand gigabytes. The tables that grow with
  expressions times token kinds (token sets and expression-rule operator
  tables) are now capped at 256 MiB and counted before they are allocated.
  FIRST sets are shared wherever they are equal by construction, and FOLLOW
  sets are built only where they are read, so real grammars are unaffected
  and large ones shrink.
- **Size and nesting.** Schematics are capped at 8 MiB. Nesting is capped at
  64 levels in total — header and dotted-key parts, arrays, and inline tables
  together; the separate caps multiplied to about 4,096 levels, which
  overflowed a 256 KiB stack.
- **Linear duplicate checks.** Duplicate keys and duplicate capabilities are
  found through ordered maps; the scans they replace were quadratic in a
  table's size.

## Changed

- `#![deny(warnings)]` is removed from the crate root, so a new compiler or
  Clippy warning cannot break a downstream build; CI keeps `-D warnings` in
  `RUSTFLAGS`.

## Measurements

Peak heap, measured with a counting global allocator (x86_64 Windows,
release profile); times are wall-clock on a shared machine:

| Input | 1.0.0 | 1.0.1 |
|---|---:|---:|
| Forge: 30,000 keywords, one alternative each (regression suite) | 484 MiB, 806 ms | 133 MiB, 83–264 ms |
| Forge: 10,000 keywords, 20,000 choices (483 KB) | 168 MiB, 479 ms | 90 MiB, 83–115 ms |
| Forge: 10,000 keywords, 60,000 choices (1.3 MB) | 655 MiB, 1.7 s | 184 MiB, 196–311 ms |
| Forge: 32,000 keywords, 180,000 choices (4.1 MB) | ≈6 GiB (estimated, not run) | refused: 76 MiB, 250 ms |
| Parse: nested speculation, 12,000 statements flat (164 KB) | 35.7 MiB | 24.7 MiB |
| Parse: the same nested 60 deep (146 KB) | 252.9 MiB | 24.2 MiB |

The 6 GiB figure extrapolates the 1.0.0 measurements (about 8.7 token sets
per choice at 4 KB each); it was not run.

Criterion, Windows, the same machine back to back (shared, so ±5 % is
noise):

| Benchmark | 1.0.0 | 1.0.1 |
|---|---:|---:|
| `parse/speculative/nested_60` (new) | ~96 ms | ~38 ms |
| `parse/speculative/256KB` | ~34–38 ms | ~35–37 ms |
| `parse/mini/1MB` | ~47–51 ms | ~47–48 ms |
| `parse/json/1MB` | ~52–54 ms | ~51–52 ms |
| `parse/calc/chain_100k` | ~36–37 ms | ~35 ms |
| `parse/mini/errors` | ~22–26 ms | ~23–24 ms |
| `forge/mini` | ~41 µs | ~41 µs |

Input nested past the depth limit, where every speculation fails, measured
somewhat slower in this patch (about 52 ms against 43 ms on one 142 KB case,
with wide run-to-run variance); it is reported as an error either way.

## Verification

Run on Windows x86_64, stable (1.95), 1.99, and the 1.85 MSRV:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings                      # also +1.99
cargo clippy --all-targets --all-features -- -D warnings       # also +1.99, +1.85
cargo clippy --all-targets --no-default-features -- -D warnings  # also +1.99, +1.85
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo test --all-features
cargo test --no-default-features
cargo +1.85 test --all-features
cargo bench --no-run
```

All green. Counts (identical for every feature combination): 81 unit + 42
integration (forging) + 20 integration (parsing) + 7 property + 21 regression
+ 3 memory + 64 doctests.
